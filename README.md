# vhs

Write terminal recordings from OCaml, and record cram tests as animated SVG
images or GIFs.

[VHS](https://github.com/charmbracelet/vhs), by [Charm](https://charm.land/),
records a terminal session as an animated GIF (or a video) from a script. The
script, a `.tape` file, lists what to type and what to wait for, one command
per line. Tapes are easy to write by hand, but VHS only finds their mistakes
while recording, and when the program changes, the GIF can go on showing what
it used to do.

This library builds tapes as OCaml values and checks them before VHS runs, so
a demo can be generated by the same code that tests the program, and a change
to the demo shows up in a diff. It also turns a cram test (a file of shell
commands with the output each one must print, which dune checks) into a
recording of that test. The library records a tape itself as an animated SVG
image, which needs no other program; a GIF or a video still needs `vhs`.

![A terminal where four commands run: echo prints "Recorded without a browser"; printf prints "bold green" in bold green, "blue" in blue and "inverse" in reverse video; printf prints wide Chinese characters, an e with a combining accent and a thumbs-up emoji; and echo $((6 * 7)) prints 42](doc/demo.svg)

The recording above is [doc/demo.t](doc/demo.t), recorded natively with
`dune exec -- vhs-cram --output doc/demo.svg doc/demo.t`.

## Installation

```
opam install vhs
```

To make GIFs, you also need
[VHS](https://github.com/charmbracelet/vhs#installation) itself.

## Usage

A tape is a list of settings, the files to write, and a list of actions. The
settings and the actions are constructors and values of `Vhs`, here opened
locally with `Vhs.[ ... ]`:

```ocaml
let tape =
  Vhs.tape
    ~settings:Vhs.[ Font_size 18; Width 1000; Height 560 ]
    ~outputs:[ "demo.gif" ]
    Vhs.[ type' "dune test\n"; wait Prompt; sleep (Ms 2000) ]
```

`Vhs.type'` types text, a newline pressing Enter. `Vhs.wait Prompt` waits for
the shell prompt to come back, so the recording shows the whole output of the
command. A prompt that takes more than 15 seconds fails the recording, and
`Vhs.wait ~timeout` sets another limit. The final sleep keeps the output on
screen. `Vhs.pp` prints the tape in the format VHS reads:

```ocaml
# Fmt.pr "%a" Vhs.pp (Result.get_ok tape);;
Output "demo.gif"
Set FontSize 18
Set Width 1000
Set Height 560
Type "dune test"
Enter
Wait
Sleep 2000ms
- : unit = ()
```

`Vhs.tape` returns an error for a tape VHS would reject or partly ignore, and
names the offending line:

```ocaml
# Vhs.tape ~outputs:[ "demo" ] [ Vhs.sleep (Ms 100) ];;
- : (Vhs.t, Vhs.error) result =
Error
 (Vhs.Invalid "Output \"demo\": neither an extension nor a trailing slash")
```

A setting or a command that `Vhs` has no value for is a raw tape line,
which `Vhs.tape` checks as VHS's parser reads it. `Set WaitTimeout`, before
the first action, gives every wait without its own timeout another limit:

```ocaml
# Vhs.tape ~outputs:[ "demo.gif" ]
    Vhs.[ raw "Set WaitTimeout 30s"; type' "make\n"; wait Prompt ]
  |> Result.map Vhs.to_string;;
- : (string, Vhs.error) result =
Ok "Output \"demo.gif\"\nSet WaitTimeout 30s\nType \"make\"\nEnter\nWait\n"
```

`Vhs.Prompt` relies on the prompt VHS gives each shell it starts, which ends
with `>`, so it also holds while a command prints a line ending with `>`. A
tape that changes the prompt, or runs such a command, should wait for
something else, with a regular expression on the line under the cursor
(`Vhs.Line`) or on the screen (`Vhs.Screen`).

`Vhs.render` runs `vhs` on the tape in a given directory, which writes the
outputs of the tape there, and returns an error when `vhs` is not installed
or fails. It runs processes with
[Eio](https://github.com/ocaml-multicore/eio), so it takes the clock, the
process manager and the directory from the environment `Eio_main.run` gives
the program:

```ocaml
let make_gif env tape =
  let clock = Eio.Stdenv.mono_clock env and cwd = Eio.Stdenv.cwd env in
  match Vhs.render ~clock ~proc:(Eio.Stdenv.process_mgr env) ~cwd tape with
  | Ok () -> ()
  | Error e -> Fmt.epr "%a@." Vhs.pp_error e

let main () = Eio_main.run @@ fun env -> make_gif env (Result.get_ok tape)
```

## Recording without VHS

`Vhs.render` writes `.gif`, `.mp4` and `.webm` outputs and PNG frames, and
`Vhs.record` writes `.svg` outputs; both write the text outputs, `.txt`,
`.ascii` and `.test`. Each one refuses an output only the other writes,
before it plays anything, and names the function that writes it, so a GIF
and an SVG image of the same actions are two tapes:

```ocaml
let make_both env ~settings actions =
  let clock = Eio.Stdenv.mono_clock env and cwd = Eio.Stdenv.cwd env in
  let proc = Eio.Stdenv.process_mgr env in
  let ( let* ) = Result.bind in
  let* gif = Vhs.tape ~settings ~outputs:[ "demo.gif" ] actions in
  let* svg = Vhs.tape ~settings ~outputs:[ "demo.svg" ] actions in
  let* () = Vhs.render ~clock ~proc ~cwd gif in
  Vhs.record ~clock ~proc ~cwd svg
```

`Vhs.record` plays the tape in bash, zsh or fish on a pseudo-terminal, reads
what the shell prints with a terminal emulator that follows xterm, and
writes the screens to the `.svg` output of the tape as an animated SVG
image, and its text to a `.txt`, `.ascii` or `.test` output in VHS's format.
It takes the same arguments as `Vhs.render` but `~vhs`, and writes the
outputs to the same paths. The text holds what VHS reads after each
command, without the extra screens VHS adds while it applies the settings.
The image holds text, no script and no external resource, and animates with
CSS alone, so it plays in an HTML `<img>` and in a README on GitHub. For a
reader who prefers reduced motion, it shows its last screen, still.

```ocaml
let make_svg env tape =
  let clock = Eio.Stdenv.mono_clock env and cwd = Eio.Stdenv.cwd env in
  match Vhs.record ~clock ~proc:(Eio.Stdenv.process_mgr env) ~cwd tape with
  | Ok () -> ()
  | Error e -> Fmt.epr "%a@." Vhs.pp_error e
```

The terminal has the size VHS gives it, and the image uses the colours of
the tape's theme, named or in JSON, and VHS's window bar and margin. Wait
patterns match as Go's do. Time follows the tape: typing and sleeping take
the time the tape says, whatever the machine does around them, so the same
output, in the same frames, gives the same image; how long a command takes
to print can move its output to other frames. A `Screenshot` of an `.svg`
path writes a still SVG image there, where VHS takes a `.png` path, and
`Source` plays the lines of another tape. A few things need VHS, such as
the other shells or a colour name in a JSON theme; `Vhs.record` names them
in its error.

`Vhs.svg` draws the same image from output given with its times, such as
bytes a test captured, with no tape, no shell and no file written; it
returns the image:

```ocaml
let image =
  Vhs.svg
    ~settings:Vhs.[ Width 600; Height 200 ]
    Vhs.[ (Ms 0, "$ ls\r\n"); (Ms 500, "a.txt  b.txt\r\n") ]
```

## Recording a cram test

A cram test is a `.t` file, in the format of Mercurial's test runner that
Brodie Rao's [cram](https://bitheap.org/cram/) popularised and dune runs: each
line starting with `  $ ` is a shell command, and the lines below it are the
output it must print. The `vhs-cram` command types each command into a bash
terminal and waits for the prompt to come back before the next one, so the
recording shows each command with its output. `--print` shows the tape
instead of running `vhs`; an `.svg` output, which VHS cannot write, has no
`Output` line there:

```sh
$ printf '  $ echo hello\n  hello\n' > hello.t
$ vhs-cram --print --output hello.gif hello.t
Output "hello.gif"
Set Shell "bash"
Hide
Env VHS_CRAM_PROMPT `bind 'set input-meta on'; bind 'set output-meta on'; bind 'set convert-meta off'; __vhs_n=; __vhs_prompt() { PS1='\[\e[38;2;90;86;224m\]> \[\342\200\213\342\200\213\342\200\213\342\201\240\342\201\240\342\200\213\342\200\213\342\200\213\342\201\240\342\200\213\342\201\240\342\201\240\342\200\213\342\200\213\342\201\240\342\201\240\e[0m\]'; __vhs_n=$__vhs_n'\342\200\213'; PS2='> \[\342\200\213\342\200\213\342\200\213\342\201\240\342\201\240\342\200\213\342\200\213\342\200\213\342\201\240\342\200\213\342\201\240\342\201\240\342\200\213\342\200\213\342\201\240\342\201\240'$__vhs_n'\]'; }; __vhs=$(printf '%s\n' ${PROMPT_COMMAND+"${PROMPT_COMMAND[@]}"} __vhs_prompt); unset PROMPT_COMMAND; PROMPT_COMMAND=$__vhs; unset __vhs VHS_CRAM_PROMPT`
Type 'eval "$VHS_CRAM_PROMPT"; clear'
Enter
Wait+Line /\x{200B}\x{200B}\x{200B}\x{2060}\x{2060}\x{200B}\x{200B}\x{200B}\x{2060}\x{200B}\x{2060}\x{2060}\x{200B}\x{200B}\x{2060}\x{2060}$/
Show
Type "echo hello"
Enter
Wait+Line /\x{200B}\x{200B}\x{200B}\x{2060}\x{2060}\x{200B}\x{200B}\x{200B}\x{2060}\x{200B}\x{2060}\x{2060}\x{200B}\x{200B}\x{2060}\x{2060}$/
Sleep 1000ms
```

An output ending in `.svg`, `.txt`, `.ascii` or `.test` is recorded by
`vhs-cram` itself, with `Vhs.record` and no browser, and the others by
`vhs`. Extensions are lower case, as VHS reads them:

```
$ vhs-cram --output hello.svg hello.t
```

A setup script, given with `--setup`, runs before the first command without
being recorded. `vhs-cram` then makes the last command of bash's
`PROMPT_COMMAND`, after any prompt hook the setup installs, set the prompt to
the one VHS gives bash followed by an invisible mark, sixteen zero-width
characters that spell a digest of the cram test, and waits for that mark:
output that ends with `>`, or with a zero-width space, while its command still
runs is not mistaken for the prompt. A command that leaves bash waiting for
more input, such as an unterminated quote or here-document, makes that wait
time out, and `vhs-cram` then names the command. A wait times out after 15
seconds, or after the number of seconds `--wait-timeout` gives; the error
names the command whose prompt did not come back, when the recording is
native, and says that `--wait-timeout` waits longer. A shell that exits, as
after `exit 3`, ends a native recording at once, with its status.

## Known limitations

- vhs 0.9.0 depends on the released matrix 0.1.0 for its pseudo-terminals,
  and carries a temporary private copy of matrix's terminal core, from
  mosaic commit 858724d6 (90a3f220 and the fixes of invariant-hq/mosaic
  PRs #104-#108), in [lib/matrix_backport](lib/matrix_backport/README.md).
  matrix 0.1.0 lacks emulator fixes the native recorder needs, such as
  keeping zero-width characters, moving within scroll regions, setting tab
  stops and replying to device queries. The copy goes away once matrix 0.2.0
  is released. No test is skipped or narrowed for matrix 0.1.0, since the
  tests run against the copy.
- The native terminal answers the device attribute, status and cursor
  position queries, but not DECRQM or the OSC 11 background colour query,
  so the queries fish 4 sends as it starts go unanswered. CI tests fish 3.7
  only.
- A program that sets the cursor's shape with DECSCUSR still gets a block
  cursor in the SVG image, as the terminal does not keep the shape.
- Under heavy load on macOS, `/bin/bash` 3.2 can print `bash: child setpgid
  (N to N): Operation not permitted` as it starts a command. The command
  still runs, but the line shows on the screen and can make a wait on the
  screen fail. It is rare, and its cause is not known yet.
- `Vhs.render` reports a wait that times out as `Vhs.Failed`, with VHS's
  message in its output, where `Vhs.record` returns `Vhs.Timeout`.
- A JSON theme is read with [jsont](https://erratique.ch/software/jsont),
  which refuses invalid UTF-8 and an unpaired surrogate escape, such as
  `"\ud800"`, in a string. VHS reads them with Go's `encoding/json`, which
  replaces them with U+FFFD, so `Vhs.tape` refuses such a theme where VHS
  would not.
